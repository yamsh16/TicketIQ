# TicketIQ

AI-powered support ticket triage. Paste a ticket description and get instant
predictions for ticket type, queue, and priority (via your fine-tuned BERT
classifiers), followed by an in-depth, ticket-specific root cause analysis,
resolution steps, and preventive measures generated by a local LLM via
Ollama.

## Pipeline

```
User Ticket
   ↓
BERT Type Prediction
   ↓
BERT Queue Prediction
   ↓
BERT Priority Prediction
   ↓
Ollama (Llama3 / Mistral) — given ticket text + type/queue/priority
   ↓
Root Cause Analysis
   ↓
Resolution Steps
   ↓
Preventive Measures
```

## Prerequisites: Ollama

The root cause / resolution / prevention analysis is generated by a local
LLM via [Ollama](https://ollama.com).

1. Install Ollama (see ollama.com for your OS).
2. Pull a model:

   ```bash
   ollama pull llama3.1
   ```

   (You can use `mistral` or any other model — just update `OLLAMA_MODEL`
   in `backend/predict.py` to match.)

3. Make sure Ollama is running (it usually runs automatically as a
   background service after install; otherwise run `ollama serve`).
   By default it listens on `http://localhost:11434`.

If Ollama is not reachable when a ticket is analyzed, the app still returns
the BERT classification results, with a fallback message in the analysis
section explaining how to fix it.

## Backend setup

1. Copy your trained classifier folders and label encoder `.pkl` files into
   `backend/`, alongside `predict.py`, so the directory looks like:

   ```
   backend/
   ├── main.py
   ├── predict.py
   ├── requirements.txt
   ├── type_model/
   ├── queue_model/
   ├── priority_model/
   ├── type_label_encoder.pkl
   ├── queue_label_encoder.pkl
   └── priority_label_encoder.pkl
   ```

   Note: the `root_cause_model/` (T5) folder is no longer used — root cause
   analysis is now handled by Ollama.

2. Install dependencies:

   ```bash
   cd backend
   python -m venv venv

   # Windows (PowerShell):
   .\venv\Scripts\Activate.ps1

   # macOS / Linux:
   source venv/bin/activate

   pip install -r requirements.txt
   ```

3. Run the API:

   ```bash
   uvicorn main:app --reload --port 8000
   ```

   The model files load once at startup (this can take a minute). Visit
   `http://localhost:8000` — you should see `{"status": "ok", ...}`.

## Frontend setup

1. Install dependencies:

   ```bash
   cd frontend
   npm install
   ```

2. Configure the API URL (defaults to `http://localhost:8000`):

   ```bash
   cp .env.example .env
   ```

3. Run the dev server:

   ```bash
   npm run dev
   ```

4. Open the printed local URL in your browser.

## API

### `POST /predict/stream` (used by the frontend)

Streams the analysis as it's generated, so the UI can show the AI's response
appearing live, a few words at a time, rather than waiting for the entire
analysis to finish.

Request:

```json
{ "text": "z. VPN access not working." }
```

Response (`application/x-ndjson`, one JSON object per line):

```
{"phase": "classification", "type": "Incident", "type_confidence": 94.2, "queue": "Network & Access", "queue_confidence": 88.7, "priority": "High", "priority_confidence": 76.3, "average_confidence": 86.4}
{"phase": "chunk", "text": "The authentication failure "}
{"phase": "chunk", "text": "is most likely caused "}
... more chunks ...
{"phase": "done", "root_cause": "The authentication failure is most likely caused by...", "resolution_steps": ["Step 1 ...", "Step 2 ..."], "preventive_measures": ["Measure 1 ...", "Measure 2 ..."]}
```

1. The first line arrives almost immediately (BERT classification is fast)
   — the frontend shows the type/queue/priority cards right away.
2. `chunk` lines stream in as Ollama generates the analysis, a few words at
   a time — the frontend appends these to a "live" panel with a blinking
   cursor.
3. The final `done` line contains the fully parsed `root_cause`,
   `resolution_steps`, and `preventive_measures`, which replace the live
   panel with the structured layout.

### `POST /predict` (non-streaming)

Same input, but waits for the full analysis and returns it all at once —
useful for testing with `curl`/Postman.

Response:

```json
{
  "type": "Incident",
  "type_confidence": 94.2,
  "queue": "Network & Access",
  "queue_confidence": 88.7,
  "priority": "High",
  "priority_confidence": 76.3,
  "average_confidence": 86.4,
  "root_cause": "The authentication failure is most likely caused by...",
  "resolution_steps": ["Step 1 ...", "Step 2 ...", "Step 3 ..."],
  "preventive_measures": ["Measure 1 ...", "Measure 2 ..."]
}
```

## Tuning the analysis

`backend/predict.py` contains `STREAM_PROMPT_TEMPLATE`, which controls how
the LLM is prompted. It includes the ticket text plus the predicted
type/queue/priority, and asks for plain text with `ROOT CAUSE:`,
`RESOLUTION STEPS:`, and `PREVENTIVE MEASURES:` sections, which
`parse_analysis_text()` then splits into structured fields. Edit the prompt
to change the tone, depth, or structure of the analysis — for example, you
could ask for severity-specific guidance or include relevant runbook
references. If you change the section headers, update the regex in
`parse_analysis_text()` to match.

The chunk size for streaming (~3 words at a time) is controlled by
`min_words` in `_split_word_chunks()`.

## Notes

- CORS is open (`allow_origins=["*"]`) for local development — tighten this
  for production.
- If your dataset's original root-cause labels are too generic to fine-tune
  a model on, the Ollama approach above sidesteps that entirely by using a
  general-purpose LLM with the ticket text and classifier outputs as
  context.
